# TabShare

Go 鉴权与信令服务 + Chrome Manifest V3 扩展。共享本机的一个真实标签页，访客直接打开链接即可共同操作，使用同一标签页的页面状态和登录状态。

普通页面在访客浏览器中直接渲染 DOM，文字可选择、复制，表单使用浏览器原生控件。首次发送页面结构，之后只同步变化的节点、属性、文字和表单状态。Canvas、跨域 iframe、视频等区域从 WebRTC 视频轨道裁剪显示；发现覆盖关系或区域超出视口时，临时采用整页画面。没有音频、麦克风、录制功能。

## 本机启动

需要 Go 1.26+。Node 22+ 和 Chromium 仅用于测试。

```sh
go mod download
go build -o bin/tabshare ./cmd/tabshare
./bin/tabshare -listen 127.0.0.1:8080 -public-url http://localhost:8080 -data .data
```

首次启动在 `.data/admin-token` 中生成配对令牌。只在你自己的机器上读取该文件并填入扩展设置；不要把令牌放进分享链接。`.data/sessions.json` 保存分享标识和密钥，需保留数据目录以维持已有链接。

在 Chrome 的扩展管理页面开启开发者模式，选择“加载已解压的扩展程序”，加载本仓库的 `extension` 目录。打开 TabShare 设置，填写服务器地址和配对令牌，允许访问该服务器，勾选自动连接。

共享会话有访客连接时，源网页右下角出现 **TS 共享设置** 悬浮按钮。点击可切换 **本地模式（DOM 同步）** 或 **远程模式（WebRTC 视频）**。访客网页也有同样入口；选择保存在扩展的会话设置中，所有访客同步切换，标签页和登录状态保持。DOM 模式仍会自动为复杂区域使用画面降级；画面模式停止常规 DOM 采集，只保留视口元数据，通过 WebRTC 连续传送视频。两个模式的输入都优先使用 P2P DataChannel。

点击扩展按钮：

- **共享当前标签页**：绑定该标签页；标签页关闭后，不会自动打开替代页。浏览器重启后需要重新分享，防止标签页 ID 被复用。
- **创建可复用的网址分享**：相同浏览器配置和相同网址返回相同分享链接。优先复用该会话原标签页，即使它已经导航到其他页面；原标签页关闭后，下一位访客连接时复用已打开的匹配网址，或新建一个后台标签页。
- **停止并撤销链接**：立即拒绝后续访问；撤销状态在服务重启后仍保留。

网址匹配去掉 fragment，保留路径和 query。不同路径或 query 是不同的网址分享。多个访客共用同一个标签页，输入按源浏览器接收顺序执行；上限为每个会话 32 名访客。多人同时编辑同一表单时，仍会互相影响，不是独立的账号或独立页面副本。

首次配置和创建分享由浏览器所有者主动完成。之后不逐次询问访客加入，支持自动连接与恢复。Chrome 自己的调试提示保持可见。共享电脑需要开机、Chrome 运行且能连接服务器；Go 服务器没有直接访问本机浏览器的能力。

## 不同屏幕与共享视口

访客设置中的 **我的显示** 独立生效并保存在当前浏览器：

- **适应窗口**：保持比例，完整显示共享视口；随窗口大小、横竖屏、全屏和软键盘可用空间变化更新。
- **适应宽度**：按可用宽度显示，可在访客窗口上下平移查看；**原始尺寸**和 **25%–200% 自定义缩放**可横向、纵向平移。
- **全屏**：扩大页面显示区域，保留退出按钮和悬浮设置；不支持浏览器全屏的设备使用沉浸显示。

本地显示缩放保留源网页的布局，使用 CSS 像素换算点击与滑动位置，DPR / Retina 像素密度单独处理。调整本地窗口或缩放不会要求源端重发全量 DOM 或新增截图。DOM 模式可使用本地原生触控滚动；整页画面模式支持触摸点击、滑动滚动及屏幕键盘输入。

需要真正按访客窗口重新排版时，勾选 **按我的窗口自动调整共享视口**。扩展调整同一个真实标签页的页面视口及像素密度，源网页 CSS 媒体查询和 resize 行为随之生效，所有访客看到同一份响应式布局。一个标签页共用一套真实视口；最近勾选此项的访客驱动尺寸，其他访客停止跟随并继续独立缩放。驱动者横竖屏切换会更新共享视口与屏幕方向；尺寸更新去重并防抖 450ms。源网页登录状态、标签页和会话保持。

取消跟随、点击 **恢复源浏览器视口** 或当前驱动者断开时恢复浏览器原视口；旧驱动者离开不会覆盖新的驱动者。暂停和连接断开也会清理扩展设置的视口覆盖。共享网页打开的弹出页继承当前共享视口。

共享视口的宽度限制为 320–3840 CSS 像素、高度为 240–2160，DPR 限制 1–2，并将截图尺寸控制在每边 4096 像素及约 830 万像素以内。复杂大画面超过中继单帧预算时逐级降低 JPEG 质量；WebRTC 视频目标 30 fps、每访客最高 4 Mbps，由浏览器根据网络和编码能力自适应；应急截图仍受独立预算约束。原生系统控件、字体绘制和移动浏览器的键盘行为会随设备变化，不能保证所有网站都在不同设备上逐像素一致。

## 公网部署

Go 同一进程提供 HTTP/WebSocket、STUN 和 TURN，无需单独部署 coturn。扩展和访客都主动连接服务器，共享电脑不需要开放入站端口。

提供 Docker Compose + Caddy 配置，自动重启并保留数据。在仓库根目录运行：

```sh
export TABSHARE_DOMAIN=tabs.example.com
export TABSHARE_TURN_PUBLIC_IP=你的服务器公网IPv4
docker compose -f deploy/compose.yaml up -d --build
```

域名需解析到服务器。防火墙、安全组和 NAT 需放通并保持端口一一映射：

| 用途 | 端口 |
| --- | --- |
| Caddy HTTP/HTTPS | 80/TCP、443/TCP |
| 内置 STUN/TURN | 3478/UDP、3478/TCP |
| TURN 中继分配 | 49160–49359/UDP |

通过服务器上的 Docker 卷安全读取 `/data/admin-token` 并配置扩展。内置 TURN 自动生成并持久保存 `/data/turn-secret`（0600），自动向已加入会话的两端下发临时凭据；无需在插件或访客端手填 TURN。公网扩展地址必须使用 HTTPS。部署文件已提供，云任务没有替你配置公网域名、防火墙或申请证书。

直接运行二进制时，TURN 默认关闭；在 HTTPS 反向代理后使用以下参数启用：

```sh
./bin/tabshare -listen 0.0.0.0:8080 -data .data \
  -public-url https://tabs.example.com \
  -turn-listen 0.0.0.0:3478 -turn-public-ip 你的服务器公网IPv4
```

`-turn-public-ip` 是对外公布的 IPv4；`-turn-relay-ip` 可指定本机绑定地址，默认跟随监听地址。`-turn-host` 可改为解析到该 IP 的域名，`-turn-relay-ports` 可改分配范围（同时修改端口映射）。Docker 默认使用上表的固定范围。

## WebRTC 和 P2P

DOM、本地表单输入与图片/字体优先走 WebRTC DataChannel；状态、输入和资源分开，16 KiB 分片、可靠有序传输，限制缓冲区和接收对象大小。远程模式使用视频轨道；DOM 模式仅在可见复杂区域需要时启动视频，同一轨道在访客端裁剪到相应区域，覆盖关系复杂时显示整个视频视口。没有音频轨道。

Chrome MV3 service worker 不提供 RTCPeerConnection，扩展在 offscreen document 中维护连接。手动共享当前标签页时尝试原生 `tabCapture`；Chrome 需要所有者先点击扩展，流 ID 也只能短时间内使用。自动重开的网址标签页及原生捕获不可用时，使用 CDP `Page.startScreencast` 连续获取共享标签页画面，送到 canvas 视频轨道再由 WebRTC 编码。没有合成帧的后台标签页使用自适应截图补充视频源：变化时目标 30 fps，不变时降低采样并跳过重复画面；浏览器自身限制后台页面脚本/动画时，无法强迫原网站按 30 fps 绘制。此路径在本机有 JPEG 解码及再次编码开销；JPEG 帧不经 Go 服务转发。它无法绕过 Chrome 捕获授权，扩展调试标识保持可见。关闭/暂停会话时释放视频；没有复杂区域的 DOM 模式停止视频采集。

优先直连，两端用 ICE/STUN 协商；内置 TURN 启用时也提供 STUN。默认额外 STUN 为 `stun:stun.l.google.com:19302`，可通过 `-stun` 改成自有服务或设为空（仅用内置 STUN）。直连失败时使用 TURN 中继，DOM DataChannel 和视频都适用，WebRTC 保持端到端加密；Go 的 TURN 不解密数据。初始化协商阶段或 WebRTC 不可用时，WebSocket/HTTP 应急传输也会经过 Go。页面显示当前 `P2P 直连`、`TURN 中继` 或 `WebSocket 兜底`。连接失败后每 5 秒重试，服务重新签发凭据给两端，避免无人值守运行超过 24 小时后使用过期凭据。

内置 TURN 只接受仍在分享会话中的临时账户，凭据有效期为 24 小时。访客退出或撤销分享时清理其分配；每个临时账户最多 8 个分配/待分配，全局最多 256 个分配，并受实际端口池容量限制。默认拒绝访问服务器内网、回环和云元数据等保留地址；可信局域网部署可显式加 `-turn-allow-private-peers`。当前 TURN 中继分配支持 IPv4 UDP，通过 TURN/UDP、TURN/TCP 或可选 TURN/TLS 承载。每位访客独立建立连接，源端上传/编码负载随访客数量增长，中继时服务器也承担相应带宽。

需要 TURN/TLS 时，给同一个 Go 服务追加：

```sh
-turn-host turn.example.com -turn-tls-listen 0.0.0.0:5349 \
-turn-cert /path/to/fullchain.pem -turn-key /path/to/privkey.pem
```

证书需被客户端信任且匹配 TURN 域名；证书/私钥在每次 TLS 握手时重新读取，支持外部续期。需额外开放 5349/TCP，Docker 还需挂载证书并映射端口。默认 Caddy 的 HTTPS 443 不直接承载 TURN；只允许 443 出站的网络需要独立 IP/端口规划。私钥、TURN 密钥和管理员令牌不能提交到 Git 或发给访客。

仍支持外部 TURN REST 服务：保持内置 TURN 关闭，在 Go 的环境配置中设置 `TABSHARE_TURN_URLS`（逗号分隔）与 `TABSHARE_TURN_SECRET`（至少 32 字符，须与外部 TURN 一致）。临时密码下发到两端，共享密钥不下发。

## Tag 自动构建

推送任意 tag 到 GitHub 时，`.github/workflows/tag-build.yml` 自动运行 Go race 测试、`go vet` 、扩展控制器测试及真实浏览器协议集成测试。通过后构建 Linux、macOS、Windows 的 amd64/arm64 服务端，以及 Chrome 插件 ZIP；产物带 SHA-256 校验文件，在对应 Actions 运行的 Artifacts 中保留 30 天。工作流也支持手动运行。

例如，在准备发布的主分支提交上创建并推送标签：

```sh
git tag v0.4.1
git push origin v0.4.1
```

本地创建标签不会触发 GitHub 构建，必须将标签推送到远端。当前工作流上传构建产物，不自动创建 GitHub Release。

## 差异同步与资源预算

源标签页的隔离脚本用 `MutationObserver` 收集变化。相同节点的多次变化合并，默认最多每 200ms 发送一批。只计算受影响节点的样式，不每批扫描整棵 DOM；class/style 变化需要更新受影响子树。初次连接、导航和明确的重新同步发送完整结构；新访客通过 DataChannel 从源端合并缓存接收初始化快照；后续只收差异，不重新扫描整页，也不给已有访客重发全量。应急 WebSocket 通道使用服务端缓存。

常规 DOM 增量的软预算为每标签页 128 KiB/s。超过预算的批次会延迟下次同步，期间继续合并变化；初始结构不计入此持续预算。WebRTC 视频没有 2 帧/s 截图限制，目标 30 fps、最高 4 Mbps。仅 WebRTC 未建立或失效时的应急截图最多 2 帧/s，软预算 64 KiB/s。预算是调度上限，单个批次、首次结构以及 WebSocket/JSON 开销可能产生短时突发。多个不同分享链接绑定同一标签页时，当前实现会分别转发，流量随链接数量增加。

图片、背景图和字体通过源浏览器的资源缓存读取，必要时仅对已加载的 URL 使用源浏览器网络上下文补读，支持跨域和需登录的资源。资源优先通过独立的可靠 DataChannel 分片发送，DOM 增量中只携带短资源标识，访客验证 SHA-256 后生成本地 Blob URL。WebRTC 失效时才上传 Go 中继，服务器按 SHA-256 去重。资源使用独立 256 KiB/s 软预算，单个对象可短时突发；单资源上限 8 MiB、会话最多 256 项 / 32 MiB、服务器全局 128 MiB，源端和访客端也有 32 MiB 资源缓存上限。导航、最后一名访客离开、浏览器断开或撤销时清理服务器资源，资源不会落盘。浏览器无法读取或预算超出时自动整页画面降级。

静止页面不发送 DOM 数据，连接保活每 20 秒一次。CSS 动画使用可读取的 keyframes 在访客端本地播放，不采样每帧动画样式。JavaScript 动画产生的 DOM 变化按批次合并，可能降低动画流畅度。原页面复杂度、资源大小和网络延迟都会影响体验；这不是对所有网站都保持原生表现的保证。

## 安全和兼容性

分享密钥是随机的 256 位 capability，放在 URL 的 `#` 后，不进入 HTTP 请求路径。持有完整链接的任何人都有页面控制权，请仅分享给可信的人。配对令牌只能保存在受信任的扩展和服务器中。服务端只允许固定的页面控制操作，不接受访客传入任意 CDP 命令或 JavaScript。

镜像 iframe 禁止执行原网页脚本、表单提交和外部网络访问。原网站 JavaScript 继续在源标签页执行；镜像只渲染经过白名单处理的元素、样式和状态。登录 Cookie 不会复制到服务器或访客。已填写的密码不传入 DOM 镜像。画面降级会包含所共享视口中的可见内容。服务端保留运行中的 DOM 状态和会话信息；管理员可以看到经中继传送的页面内容，因此需要使用可信服务器。

已适配 `::before` / `::after` / dialog `::backdrop`、可读取的字体和 keyframes、通过 CDP 解析的封闭 Shadow DOM、富文本选区与可信源端输入、单选下拉框的可信键盘提交、多选值、HTML dialog/popover，以及 alert/confirm/prompt/beforeunload 提示。提示由所有访客共同查看，首先提交的有效回答作用于源网页。共享页直接打开的弹出标签页可跟随共享（最多四层），关闭弹出页后返回来源标签页；设置中也可关闭当前弹出页。其他已有标签页不会加入共享。

一比一的实际边界：系统菜单采用访客浏览器原生控件，操作系统、浏览器版本、字体渲染和控件外观仍会有差异。多选与单选键盘路径不适用时使用受限的 DOM 事件提交。富文本的复杂插件、跨框架编辑行为、封闭组件样式变化、CSS 特殊绘制和不可读取资源不能保证完全复现，可用悬浮设置切换整页画面。DOM 有 3500 节点及约 3 MB 采集预算，超过预算会整页画面降级；服务端有 4 MiB 状态上限。只跟随已共享页作为 opener 创建的弹出页，不扫描或加入其他页面；暂停、断线或浏览器重启后的未关闭弹出页不会自动恢复，原主标签页仍按原会话复用。分享没有实现域名锁、文件传输、浏览器桌面或系统操作。

## 测试

```sh
go test -race ./...
npm ci --ignore-scripts
npm test
go build -o bin/tabshare ./cmd/tabshare
# 字体资源测试默认使用 Linux DejaVuSans.ttf；可通过 TEST_FONT_PATH 指定 TTF
CHROMIUM_PATH=/usr/bin/chromium TEST_RTC=0 npm run test:e2e
CHROMIUM_PATH=/usr/bin/chromium TEST_TURN=1 npm run test:e2e
```

浏览器集成测试使用真实 Chromium、真实 Chrome DevTools Protocol 和真实访客页面。由于云环境管理员策略禁止加载自定义扩展，测试用 Chrome API 适配器运行原始 `worker.js`，没有修改管理员策略。WebRTC 测试运行原始 offscreen 模块，使用真实 RTCPeerConnection、TURN/TCP、视频编码器和访客解码器；云端策略禁用非代理 UDP，不能验证直接 UDP 穿透。测试直接启动同一个 Go 服务的内置 TURN，仅监听回环地址，并强制 relay 候选验证中继。这验证浏览器控制、页面同步、会话和 WebRTC / 中继链路，但不代表已验证 Chrome 扩展安装、权限提示或 MV3 生命周期；这些仍需在允许加载扩展的本机 Chrome 中检查。
