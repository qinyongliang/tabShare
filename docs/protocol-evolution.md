# 增量同步协议演进草案

状态：设计草案，未改变线上协议。候选 Protobuf 子集见 `benchmarks/protocol.proto`，不可直接拿来替换完整生产格式。

## 保留三条链路

1. state：可靠、有序的 DOM patch、文档元信息、初始化快照。
2. input：独立可靠、有序的输入事件；相邻未执行鼠标移动可合并，按键/点击不能丢失或跨顺序。
3. assets：哈希校验的二进制图片/字体/下载块；不要 Base64 包在 DOM 消息里。
4. 像素：WebRTC 视频轨道传动态 Canvas/WebGL/视频区域，数据通道传区域布局；不是把静态图片一律视频化。

## Envelope 与协商

新版本先通过已有兼容信令交换协议版本和 codec 列表，例如 json-v1 与 protobuf-v2。双方明确确认后才启用新编码，否则继续 json-v1。不能把旧版本不认识的类型直接发送出去。

每个状态消息至少包含 protocolVersion、documentEpoch、sequence、baseSequence、kind、payloadLength。

- documentEpoch 每次导航/重建变化，拒绝旧文档的迟到包。
- sequence 单调递增；patch 的 baseSequence 必须是接收端当前序号。
- 序号不一致时请求一次重新同步，等快照建立后恢复；不能继续应用缺失中间状态的 patch。
- snapshotBegin/chunk/end 在新缓存中构建，完成并校验后切换，避免把不完整快照冒充完整页面。
- 分片继续携带 messageId、totalLength、offset，限制总长度、并发重组数及超时。
- 解压前验证声明长度，解压中执行输出上限，不依赖压缩包长度防止内存放大。

## Patch 语义

nodeId 只在当前 documentEpoch 内有效。patch 区分 create、update、remove 与 children order。

- 未出现字段：不变化。
- 显式 null/delete：删除属性，不等于空字符串。
- 文本空字符串：合法更新。
- children 空数组：清空子节点，不等于不更新。
- 样式字典局限单包；跨包字典若要复用，必须带字典 epoch、重连恢复和容量上限。
- 服务端中继和新访客缓存必须理解相同语义，不能只升级扩展和浏览器。
- 任何压缩或二进制化都不能改变资源权限、密码输入脱敏、脚本过滤、SVG 清洗。

## 实时与背压

变化到达后短窗口合并，不使用无限延后的 debounce。输入相关 patch 优先，但不能越过结构依赖。持续 CSS 动画优先本地 keyframes，JS 动画评估局部视频或增量频率。

队列高水位应合并尚未编码、且语义可合并的节点字段；已经发送的序列不可撤回。无法保持一致时显式 resync。发送缓存低水位事件恢复，避免忙轮询。分别限制压缩前对象、编码队列、浏览器 bufferedAmount、接收重组和解压缓冲。

## 视频区域

区域描述带 documentEpoch、layoutRevision、nodeId、源矩形、输出图集矩形和裁剪/遮挡信息。布局变化必须与视频显示对齐；旧布局帧不可错误覆盖新页面。稀疏区域合成一个图集优先于每个节点建立一个 PeerConnection/视频编码器。

静止图片用内容哈希缓存；只有动态高频画面或 DOM 无法表达的区域才用视频。考虑视频编码、GPU 读回、CDP JPEG 解码再编码、多人上传倍增和 TURN 回退成本。不能仅凭“P2P”断言更快。

## 上线门槛

先用同一真实页面数据比较 JSON+现有池化+gzip、候选二进制+同等压缩，再看 p50/p95/p99 变化到显示延迟、输入响应、长任务、CPU、堆和外部缓冲、带宽。至少覆盖初始化、大列表更新、连续输入、删除/移动节点、跨页面、新访客、断线重连、局部 Canvas、1/5/10 访客弱网、错误长度/序号/解压包。

只有浏览器端到端收益可重复且无一致性回退，才考虑默认启用。保留旧版本协商回退，先灰度，不进行无基准的大框架替换。
