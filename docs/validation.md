# 云环境验证记录

## 0.6.0 当前验证

共享页铺满访客视口，外层地址栏、状态栏和页脚收进可拖拽的“共享设置”。源端按钮不进入镜像。浏览器原生后退/前进通过 hash 和源历史条目 ID 控制同一标签页，包括 SPA 和刷新恢复；不复制加入前的历史。DOM 超预算或局部视频被遮挡时继续保留 DOM，不再切整页视频。

本轮修复了页面导航后 isolated world 失效时的 `Cannot find context with specified id`，过期输入被丢弃并重新获取上下文。样式同步改为标准计算属性与共享默认值，清除旧 body 边距，保留根字体、SVG 命名空间、渐变/裁剪、本页及外部符号引用、CSS SVG 遮罩和转义后的内嵌 data SVG。4031 节点的嵌套样例分批同步完成，后到子节点正确挂回父节点；图标样例用真实资源读取、SHA-256 校验与 SVG 清理链路比较源端/镜像尺寸及像素，通过检查。

两名真实 WebRTC 访客的回归通过：右键原生输入控件、网页自定义右键菜单、Ctrl+V 图片经二进制 P2P 送达，源网页收到 `isTrusted=true` 的原生粘贴事件，且只粘贴一次。图片操作增加 `clipboardWrite` 权限，会在明确粘贴时替换源电脑系统剪贴板中的图片，不读取源端剪贴板。页面滚动、中文/富文本、封闭 Shadow DOM、跨域图片/字体、弹出页、手机与 4K 布局、重连和撤销继续通过。

Go race/vet、38 项 Node 检查、资源/图标/媒体专项、完整 `TEST_TURN=1` 与 `TEST_RTC=0` 浏览器回归、工作流 actionlint 均通过。1、5、10 名真实 TURN/TCP 访客以及 10 人持续 30 秒传输测试通过，覆盖压缩差异、输入、区域视频、64 KiB/s 限速连接、重连与队列释放；应用发送队列峰值约 256 KiB。此负载样例不包括任意网站的采集成本，不能作为整个应用的并发容量承诺。

局部视频为真正的 WebRTC 视频轨道；CDP 与原生捕获均先在源端裁剪区域再编码。后台源页启用 focus emulation，前台访客的空闲补帧等待上限降至 250ms，输入后提前采样，接收端请求较低播放缓冲。最后一轮受控 Canvas 样例在 2.1 秒解码 45 帧，三次绘制到可见延迟为 77、408、95ms；此前轮次仍出现过超过 1 秒的峰值，不能声称延迟已消除，也不能将该机器的 TURN/TCP 样例视为公网或原生 tabCapture 的性能保证。实际点击扩展后的原生捕获路径仍需在允许安装扩展的 Chrome 中验证。

实时 GitHub Issues 和 Wikipedia 页面保留 DOM，通过两名访客显示、滚动、输入/导航检查，未达到节点预算。最终代码另完整重跑 GitHub，通过搜索输入与提交、滚动和导航；加载完成后的 5 秒观察窗口没有新增 DOM 批次，不能据此推断整个连接没有保活流量。Go 文档交互通过，但统计脚本被云网络拦截。Google 搜索、YouTube 和 OpenCode 登录页的直接访问被当前 HTTPS 代理策略拦截，未完成对应线上页面验证；本地图标样例不是 OpenCode 实站验收。测试仍使用 Chrome API 适配器运行原始 worker、真实 CDP/offscreen/RTCPeerConnection 和内置 Go TURN/TCP，不覆盖管理员策略禁止的实际扩展安装、权限提示及 MV3 生命周期。

## 0.4 WebRTC 验证（历史记录）

Go race / vet、14 项 Node 检查、独立 TURN fixture 构建与 vet、tag 工作流 actionlint 和 Compose 配置解析均通过。分别执行了 `TEST_RTC=0 npm run test:e2e` 和 `TEST_TURN=1 npm run test:e2e`，两套完整浏览器检查均通过。

WebRTC 检查运行真实浏览器中的原始 offscreen 模块及 RTCPeerConnection，使用仅监听回环地址的 Pion TURN/TCP fixture。测试仅把 PeerConnection 的 ICE 策略设置为 relay 以确定性验证 TURN，不修改 Chrome 管理员策略。生产连接继续优先直连。验证了：

- 两名访客通过可靠 DataChannel 操作同一标签页；DOM 差异和输入不经 Go WebSocket 转发。
- 源 Cookie 资源读取后，SVG 图片、背景图和 TTF 字体通过二进制 DataChannel 到达；检查这段期间 Go 资源上传数量没有增加。
- 主动关闭真实 PeerConnection 后，恢复完整兜底 DOM，原标签页仍可操作，并在无所有者操作时自动重新协商 WebRTC。
- 手机视口与 DPR=2、视频触控、横竖屏、多人尺寸驱动、恢复布局；DOM 与视频模式切换、诱导弹出页和返回。
- Canvas 区域视频和点击，重叠浮层切换整页视频，移除后恢复区域。CDP 在真实源页持续绘制 Canvas，访客在 2.1 秒解码 21 帧，超过应急截图每秒 2 帧限制；这是本机测试结果，30 fps 是目标而非保证。
- 自动新建的后台标签页视频初始化。无合成帧时自适应补充截图，重复画面跳过；视频经 WebRTC 编码，JPEG 不通过 Go 转发。
- 视频区域元数据按 DOM 文档版本隔离，导航后不会把旧 Canvas 区域覆盖到新文档的文字或富文本节点。

直接 UDP 穿透、真实公网 TURN/coturn 防火墙、原生 tabCapture 授权及 MV3 offscreen 文档生命周期未在此云策略环境验证。原生 tabCapture 路径提供实现，需所有者在允许安装扩展的本机 Chrome 检查；无人值守重开的网址页采用调试视频来源。Compose 的可选 coturn profile 已校验配置，没有在公网启动。

## 0.5.1 容量与原生视频优化

新增跨会话 DOM 缓存预算（默认 64 MiB），节点、CSS、元数据共同计账，超额增量不会部分提交。全部访客使用 WebRTC，或最后一名应急访客离开后，释放重复的 Go DOM/资源缓存。修复仅经 P2P 导航后新增应急访客缺少缓存图片/字体的情况；完整 WebRTC 回归新增真实访客检查，验证 HTTP 资源恢复、字体加载和离开后缓存归零。迟到上传返回 202，不保留错误的已送达标记。

内置 TURN 增加合计 50 Mbps 的双向载荷令牌桶（最多 256 KiB 突发），超额丢弃而不积压，增加丢弃字节和预算诊断。Go race 回归覆盖全局缓存拒绝与恢复、CSS 预算、仅影响对应应急会话、P2P/应急切换回收、并发令牌消耗、双向 UDP 丢弃及恢复，且 TURN/TCP 的鉴权与实际分配仍可用。24 项 JavaScript 检查通过，包括新资源送达标记和丢包/CPU/RTT/显示尺寸的编码预算。

原生来源新增一份共享裁剪画布，整页模式直接使用原始轨道，避免整页模式的额外复制。真实 Canvas MediaStreamTrack 检查通过：640×360 来源中的 100×60 红色区域像素正确，整页/局部切换、后台限帧、暂停和轨道释放正常。新的实际 TURN/RTP 传输检查还验证访客解码尺寸从 100 切为 640，再恢复为 100。该合成来源验证媒体处理管线，不验证 Chrome tabCapture 的用户授权。

`npm run test:transport` 的 1、5、10 名访客阶段通过。10 人持续 120 秒通过 DOM 差异、输入、区域视频、连接替换和队列释放；一名访客通过上限 64 KiB/s、初始延迟 75 ms 的本地 TCP 限速器，其余访客保持响应。120 秒样例发送 577 批差异，最后序号 578，最少解码 1048 帧（含中途替换访客）；应用发送队列峰值约 256 KiB，不包括浏览器内部缓冲与编码开销。最终代码的默认 30 秒回归也通过。限速器不模拟随机丢包，样例输入计时是协议层检查，不能当成真实用户端到端延迟或公网容量承诺。

## 0.5.2 真实网站检查

2026-10-15 使用 `npm run test:sites` 访问实时公开网站，未用本地页面代替网站内容。源端运行原始 worker 主体及资源模块，通过 Chrome API 适配器连接真实 CDP，两名访客使用原始网页和同一 Go 服务的 TURN/TCP。浏览器保留 HTTPS 代理和证书校验；为 Chromium 初始化已存在的 NSS 证书数据库，仅授予该数据库目录写权限，没有关闭证书校验或修改管理员策略。此检查不覆盖实际扩展安装、权限和 MV3 生命周期，也不证明公网 P2P 穿透。

| 网站 | 实际渲染 | 已通过的交互 | 未完成的范围 |
| --- | --- | --- | --- |
| GitHub microsoft/TypeScript Issues | 整页 WebRTC 视频 | 双人显示、搜索输入与提交、滚动、导航至仓库页 | 图片代理 camo 域名被网络拦截；不证明原生 DOM 兼容性 |

这一轮 GitHub 初始约 2178 个元素、116 个 SVG 和 36 个自定义元素；Wikipedia 初始约 4171 个元素。DOM 预算同时包含文本节点及样式字节，不能仅按元素数量判断能否保留 DOM。三站已执行的交互断言均通过，但因资源/脚本未完整加载，报告标为 `partial-network-blocked`；YouTube 标为 `blocked`，整条真实网站命令按预期返回非零。没有把跳过项计为成功。报告中 `render` 是初始显示模式，导航后的降级另见 `capture` 与 `videoFallbacks`。

实测修复了导航期间并发创建 isolated world 导致空/失效 context ID、非安全初始上下文缺少 randomUUID、超限 DOM 反复重建残缺大快照、隐藏的响应式菜单请求未加载背景图导致误降级，以及多栏与裁剪 CSS 丢失。采集超时/超预算后只发送视频所需的轻量元数据。新增并发初始化、导航过期与采集超时回归，Node 检查共 27 项；真实浏览器专项检查另验证隐藏背景图延迟同步、显示后加载、双栏位置保持和嵌套大 DOM 的轻量降级。访客页脚现在显示实际 DOM/视频状态。

本轮 GitHub 与 Wikipedia 分别只产生约 5.7 KB、4.7 KB 的原始 DOM 消息（含导航和初始化）；三站最后五秒都没有新 DOM 批次。视频和 ICE 协议仍有流量，报告单独记录 RTP/DataChannel/ICE 接收统计，不能把 DOM 静止当作整条连接零流量。这些数字只描述该轮页面与机器，不是网站兼容性或公网成本保证。
