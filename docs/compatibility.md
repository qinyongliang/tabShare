# 安全、兼容性与限制

[返回 README](../README.md)

## 访问与数据边界

分享密钥是随机的 256 位 capability，放在 URL 的 `#` 后，不进入 HTTP 请求路径。持有完整链接的任何人都有页面控制权，请仅分享给可信的人。配对令牌只能保存在受信任的扩展和服务器中。服务端只允许固定的页面控制操作，不接受访客传入任意 CDP 命令或 JavaScript。

镜像 iframe 禁止执行原网页脚本、表单提交和外部网络访问。原网站 JavaScript 继续在源标签页执行；镜像只渲染经过白名单处理的元素、样式和状态。登录 Cookie 不会复制到服务器或访客。已填写的密码不传入 DOM 镜像。画面降级会包含所共享视口中的可见内容。服务端保留运行中的 DOM 状态和会话信息；管理员可以看到经中继传送的页面内容，因此需要使用可信服务器。

访客明确粘贴图片时，扩展使用 `clipboardWrite` 将该图片写入源电脑剪贴板，然后在共享页执行粘贴；不会读取源电脑剪贴板。图片优先通过 P2P，HTTP 应急上传只转发给源浏览器，不落盘。PNG/JPEG/WebP/GIF 上限 4 MiB，每访客每秒一次；非 PNG 转换另受 1600 万像素上限约束。

## 已适配内容

已适配 `::before` / `::after` / dialog `::backdrop`、可读取的字体和 keyframes、通过 CDP 解析的封闭 Shadow DOM、富文本选区与可信源端输入、单选下拉框的可信键盘提交、多选值、HTML dialog/popover，以及 alert/confirm/prompt/beforeunload 提示。提示由所有访客共同查看，首先提交的有效回答作用于源网页。共享页打开的新标签页在客户端作为独立共享标签页打开，保留父页；支持 window.open、target="_blank"、noopener 以及先开空白页再跳转。最多跟踪四层，每个来源页同时最多 32 个子页面；撤销父分享会同时撤销其子页面。浏览器阻止弹窗时，设置中保留可点击的新页面链接，可为共享站点允许弹窗。扩展通过 webNavigation 的来源事件识别新标签页，更新后需要接受该权限。其他已有标签页不会加入共享。

## 已知限制

一比一的实际边界：系统菜单采用访客浏览器原生控件，操作系统、浏览器版本、字体渲染和控件外观仍会有差异。多选与单选键盘路径不适用时使用受限的 DOM 事件提交。富文本的复杂插件、跨框架编辑行为、封闭组件样式变化、CSS 特殊绘制和不可读取资源不能保证完全复现，复杂区域采用局部视频补偿，不切换整页视频。DOM 分批采集，上限 30,000 节点及约 5.5MB 节点数据；服务端每文档状态上限 6 MiB。达到预算时保留已有页面，但未同步的内容可能缺失。只跟随浏览器确认来源为已共享页的新页面，不按 URL 猜测或扫描加入其他页面。子页面使用独立标签页会话；关闭后的链接不会重开新网页，浏览器重启后标签页分享仍按原有生命周期规则失效。分享没有实现域名锁、任意文件上传、浏览器桌面或系统操作。

页面下载支持共享页的 GET/POST 附件响应、带 `download` 的链接和 Blob 文件，取消 64 MiB 单文件上限，按 256 KiB 分块流式写入访客选择的文件，源端每标签页最多两个并发转发。HTTP 下载接管实际响应，避免再次提交 POST；中途连接切换会终止该文件，需要重新触发下载。需要访客点击保存并选择目标文件；不支持流式文件写入的浏览器会明确提示，不退回整文件内存缓存。未覆盖浏览器保存整个网页、Service Worker 特殊下载管线、流媒体/DRM、跨进程 iframe 中无法观测的脚本下载和任意本地文件。脚本延迟触发的 Blob 下载可能同时在源浏览器发生下载。

视频区域可读取的 input/textarea、富文本及同源 iframe 光标和选区提供输入法位置、原生复制支持。跨进程/跨域隔离、应用自绘光标无法读取时按最近点击位置放置输入代理，不能保证候选框与真实光标逐像素一致。云测试覆盖坐标与组合输入事件，没有桌面操作系统输入法的候选窗口验收。

采集超时后重新进行分批 DOM 同步。SVG 图标支持路径、currentColor、渐变、裁剪、内外部符号引用和 CSS SVG 遮罩，资源 SVG 清除脚本及外部引用；复杂 SVG 滤镜、任意形状遮挡或旋转后区域仍可能有绘制差异。原生历史映射覆盖加入分享后访问的页面；加入前的历史不会写入访客浏览器。Google、YouTube 和 OpenCode 的直接访问仍受当前云网络限制。真实网站的测试范围见 [验证记录](validation.md)。

## 视口与容量

共享视口的宽度限制为 320–3840 CSS 像素、高度为 240–2160，DPR 限制 1–2，并将截图尺寸控制在每边 4096 像素及约 830 万像素以内。复杂大画面超过中继单帧预算时逐级降低 JPEG 质量；WebRTC 视频目标 30 fps、每访客最高 4 Mbps，由浏览器根据网络和编码能力自适应；应急截图仍受独立预算约束。原生系统控件、字体绘制和移动浏览器的键盘行为会随设备变化，不能保证所有网站都在不同设备上逐像素一致。

每个分享会话最多 32 名访客。所有访客操作同一个页面，多人同时输入会互相影响。每位访客独立建立 WebRTC 连接，源端上传及编码负载随人数增长；经 TURN 时，服务器也承担中继带宽。

服务端默认共享 64 MiB 的 DOM 缓存预算，内置 TURN 默认合计 50 Mbps 中继载荷预算，允许短时突发。预算、缓存回收和超额行为见 [架构文档](architecture.md#渲染压缩和背压)，可选调整见 [部署文档](deployment.md#运行诊断)。这些上限不等于整个进程的内存上限或云厂商的计费流量。

更多 DOM、资源和传输预算见 [架构文档](architecture.md)。
